## Code rules for this course (current iOS only — no old APIs)
- SwiftUI only. Never UIKit. The one exception: when SwiftUI truly has no way to do something (for example, taking a photo with the camera), say "This needs UIKit because…" before the code, keep the UIKit part as small as possible in its own file named for what it does (for example CameraPicker.swift), and explain in one sentence what UIViewControllerRepresentable does.
- Buttons: Button("Title", systemImage: "symbol.name") { } when there is a symbol; otherwise Button("Title") { }. Style buttons with .buttonStyle(.glassProminent) and color them with .tint(...). Exception: a Button that is a cell in a grid and has its own label view (a card, an emoji tile) keeps the plain style.
- Use .foregroundStyle(...). Never use .foregroundColor(...) — it is deprecated.
- Images live in the Assets catalog. Sounds live in the Assets catalog as data assets — load them with NSDataAsset, not Bundle.main.url.
- If my project already has a playSound(soundName:) function, call it as it is. Do not rewrite it.
- Keep all code in ContentView.swift unless I ask for a new file (or the UIKit exception above applies). An enum goes inside ContentView, right after `struct ContentView: View {`, unless I say otherwise.
- Functions go below the closing curly brace of `var body`, never above it.
- Always write `return` in computed properties and in functions that return a value, even when the body is a single line. (Swift lets you leave it out; I don't, because I'm learning to read code.) A function that returns nothing does not end with a bare `return`.
- Repeated views: when the same view appears more than twice with only the data changing, use ForEach, not copies. Use ForEach(items, id: \.self) unless the type is Identifiable. For rows and columns use LazyVGrid with GridItem(.adaptive(minimum:)); do not use other grid forms unless I ask.
- Magic Strings: when the same String literal that the program depends on (a sound name, an image name, a saved-value key) is used in more than one place, put it in an enum with a String raw value and use .rawValue. A String the user merely sees (a title, a message) is not a magic String — leave it alone.
- To wait before doing something (a delay), use Task { } with try await Task.sleep(for: .seconds(0.75)) inside do / catch. Do not use DispatchQueue.main.asyncAfter.
- When something can fail (a value that might be nil, a file that might not load, a conversion that might not work), check it at the top of the function with `guard let` or `guard` and `return` early. Never let a failure do nothing silently.
- For a statement that can throw an error, use do / try / catch and print the error in the catch block. Do not use `try?` to hide the error, and never use `try!`.
- Every failed check or caught error prints one line to the console that begins with "😡 ERROR: " followed by what went wrong and the value involved. Examples: print("😡 ERROR: Could not read file named \(soundName)") and print("😡 ERROR: \(error.localizedDescription) creating AVAudioPlayer"). A guard that only ignores a normal situation (for example a tap on a card that is already face up) is not an error and gets no message.
- Do not use force unwrapping (!) on optionals.
